## 1. md 파일 읽는 순서

새로운 채팅이나 작업 세션에서 반드시 아래 순서대로 문서를 읽고 진행한다.

```
1. SHERPAIN21_MASTER_PROMPT.md (이 문서)
   → 전체 개요, 절대 규칙, 기술 스택, 플랜/눈덩이 정책

2. CURRENT_STATUS.md
   → 현재 페이즈 진행 상황, 최근 해결된 이슈, 다음 작업

3. FILE_MAP.md
   → 프론트엔드(frontend/)와 백엔드(worker/) 디렉토리 구조 및 각 파일의 역할

4. BUSINESS_LOGIC.md
   → 핵심 캐시카우(에스크로 수수료, 낙전 수익 등), 기능별 크롤링/프록시 로직 상세

5. TOPBAR_FEATURES_SPEC.md
   → 상단 5대 글로벌 메뉴(커뮤니티, 제휴사, 에스크로 등) UI 및 기능 기획서

6. STYLE_GUIDE.md
   → Profound Minimalist B2B SaaS 디자인 시스템 (컬러, 타이포, 컴포넌트)

7. SECURITY_GUIDE.md
   → OWASP Top 10, JWT 보안, SQLi/XSS 방어 및 환경변수 가이드
```

## 2. 프로젝트 본질

### 2.1 Sherpain21이란

Sherpain21은 **한국형 로컬 마케팅/운영 B2B SaaS 플랫폼**이자 **B2B2C 에스크로 중개 플랫폼**이다.

단순 웹사이트가 아니라 다음 5가지를 동시에 포함한다:

- **외부 공개용 브랜드 랜딩 사이트** (신뢰감, 가입 유도)
- **로컬 마케팅 자동화 기능이 집약된 B2B SaaS 허브**
- **B2B2C 에스크로(외주/모집) 중개 플랫폼** (핵심 캐시카우)
- **프리미엄 요금제(Plan) 및 사용량(눈덩이) 기반 내부 운영 대시보드**
- **Cloudflare Workers(API) + D1(DB) + Pages(Vite) 기반 서버리스 풀스택**

### 2.2 대상 사용자

| 역할 | 코드 | 설명 |
|------|------|------|
| 자영업자 | owner | 매장 운영자, 소상공인 |
| 마케터 | marketer | 에이전시, 프리랜서 |
| 블로거 | blogger | 에스크로 미션 수행자, 수익 창출자 |
| 프랜차이즈 | franchise | 별도 B2B 트랙 |
| 기타 | other | 텍스트 입력 |

### 2.3 브랜드 아이덴티티

- **브랜드명**: 셰르파-인 (Sherpain)
- **도메인**: `sherpa-in.com`
- **의미**: 비즈니스의 정상(성공)을 향해 길을 안내하고 짐을 덜어주는 셰르파

## 3. 절대 지켜야 할 규칙

### 규칙 1. 외부와 내부를 절대 혼동하지 않는다

- **외부 (랜딩, 인증)**: 히어로 배너, 강렬한 다크/블루 그라데이션, 사이드바 없음
- **내부 (앱/대시보드)**: Profound Minimalist 스타일 적용, 좌측 사이드바 + 우측 메인 콘텐츠

### 규칙 2. 기능보다 구조와 수익(BM)을 먼저 유지한다

새로운 기능을 추가하거나 UI를 수정할 때:
- **`BUSINESS_LOGIC.md`** 를 반드시 확인
- 눈덩이(크레딧)를 차감하는 기능인지, 무료 유도용 기능인지 파악
- 과금/방어 로직을 넣어야 함

### 규칙 3. 에스크로 로직의 트랜잭션(원자성) 보장

눈덩이가 오가는 모집/의뢰(에스크로) 백엔드 기능은 반드시:
- **10% 플랫폼 수수료 징수**
- **D1 Batch 트랜잭션**
- **유저 잔고 검증**

을 하나의 세트로 묶어서 예외(catch) 없이 안전하게 처리해야 한다.

### 규칙 4. 기존 구조를 함부로 뒤집지 않는다

- 합의된 페이지 역할(예: `board.html`에 출석체크 포함, `services.html`에 자유홍보 포함)
- 2단 모달(Split-View) 형태의 뼈대 레이아웃을 임의로 무시하고 전면 재설계하지 않음

### 규칙 5. Font Awesome 및 이모지 사용 규칙

**내부 앱 (대시보드, 사이드바)**:
- `<i class="fa-solid fa-...">` 형태의 Font Awesome 아이콘 사용 허용
- 단, **최소화 권장** (SVG 아이콘 사용 불허용)
- 텍스트 이모지(🚀, 💡 등)는 **사용 불가능**

**외부 랜딩 페이지**:
- SVG 또는 이모지 사용 불가능
- 아이콘은 Font Awesome 모두 가능

**탑바 메뉴**:
- 아이콘 사용 불가, **텍스트만** 표시

### 규칙 6. 모든 페이지는 대표님과 상의 후 생성

새로운 페이지를 생성할 때는 반드시:
1. 페이지 구조와 기능 설명을 먼저 제안
2. 대표님으로부터 승인을 받은 후 구현
3. 기능 축소는 절대 없음

## 4. 사용자 유형과 플랜/눈덩이

### 4.1 플랜(Plan) - SaaS 구독

| 코드 | 의미 | 월 요금 | 설명 |
|------|------|---------|------|
| a | BASIC | 무료 | 핵심 기능 제한적 개방 (가입 시 150 또는 추천인 1000 눈덩이 지급) |
| b | STANDARD | 3.9만~5.9만 | 소상공인 최적화 |
| c | PRO | 9.9만~18.9만 | 전문 마케터/대행사 최적화 |

### 4.2 눈덩이 - 하이브리드 결제

눈덩이(크레딧)는 아래 고급 리소스 사용 시 유저의 잔고에서 즉시 차감된다:

| 기능 | 눈덩이 차감량 | 무료 혜택 |
|------|------------|----------|
| 소상공인 데이터 (010 수집) | 건당 차감 | Basic 1회, Standard 월 1회, Pro 월 3회 |
| 부동산 데이터 수집 | 건당 차감 | - |
| 사진 메타정보 변경 | 300 눈덩이 | - |
| 자유홍보 게시판 글쓰기 | 500 눈덩이 (1회 초과 시) | 전 플랜 일 1회 무료 |

### 4.3 에스크로 (핵심 캐시카우)

| 구분 | 내용 |
|------|------|
| 보상금 예치 | 의뢰 등록 시 총 비용의 10% 플랫폼 수수료 포함하여 즉시 차감 |
| 수행자 독점 | 한 명이 수락하면 미션 잠금 (is-locked) |
| 정산 | 승인 시 보상금 - 수수료 차감 후 수행자에게 지급 |
| 낙전 수익 | 최소 10,000원 이상 시 출금 가능, 미달 시 회사 수익 귀속 |

## 5. 기술 스택

| 영역 | 기술 |
|------|------|
| **프론트엔드** | HTML / CSS / Vanilla JS (Vite 빌드, Obfuscator 난독화) |
| **백엔드/API** | Cloudflare Workers (`nodejs_compat` 적용) |
| **데이터베이스** | Cloudflare D1 (SQLite) - `schema.sql` 관리 |
| **인증 보안** | Web Crypto API (SHA-256 해싱), 커스텀 JWT |
| **배포/호스팅** | Cloudflare Pages (Frontend, `sherpa-in.com`) |
| **코드 관리** | GitHub Private Repository |
| **결제** | 토스페이먼츠 / 네이버페이 (예정) |
| **차트** | Chart.js |
| **마인드맵** | D3.js |
| **아이콘** | Font Awesome 6 (내부 앱), SVG (선호) |

## 6. 버전2 새로운 구조

### 6.1 버전1 vs 버전2 주요 변경사항

| 구분 | 버전1 (Sherpain) | 버전2 (Sherpain21) |
|------|------------------|-------------------|
| **브랜드** | SHERPA IN | Sherpain21 |
| **BM** | 단순 SaaS | SaaS + 에스크로 + 눈덩이 이코노미 |
| **폴더** | docs/ | frontend/ + worker/ |
| **빌드** | GitHub Pages 직접 호스팅 | Vite 빌드 + Cloudflare Pages |
| **사이드바** | 다크 네이비 (#1e293b) | 화이트 사이드바 + 프로필 영역 + 접기/펼치기 |
| **탑바** | 없음 | 커뮤니티/제휴사/에스크로/문의/고객센터 (텍스트 only, 아이콘 없음) |
| **게시판** | 없음 | 커뮤니티/자유홍보/에스크로 게시판 |
| **플랜** | Basic/Standard/PRO | Basic/Standard/PRO + 눈덩이 |
| **베이스 컬러** | #4A6CF7 (블루) | #0D1B2A (다크 네이비) + #2563EB (딥 블루 accent) |

### 6.2 Vite 빌드 환경

```javascript
// vite.config.js 핵심 설정
{
  build: {
    minify: 'terser',
    rollupOptions: {
      output: {
        manualChunks: {
          'chart': ['chart.js'],
          'd3': ['d3']
        }
      }
    }
  }
}
```

### 8.2 사이드바 접기/펼치기

| 상태 | 너비 | 표시 |
|------|------|------|
| **펼침 (기본)** | 260px | 로고+텍스트, 프로필 상세, 메뉴 텍스트, 배지 |
| **접힘** | 72px | 로고 아이콘만, 카테고리 아이콘만, 프로필 아바타만 |

- 접기 토글: 사이드바 헤더의 `◀` 버튼 또는 탑바 좌측의 접기 버튼
- 상태는 `localStorage('sherpa_sidebar_collapsed')`에 저장하여 새로고침 후에도 유지
- `body.sidebar-collapsed` 클래스로 CSS 제어

## 13. 작업 방식 규칙

### 13.1 새 페이지 생성 시 流程

```
1️⃣  대표님께 제안
   ├── 페이지 목적 및 기능 설명
   ├── 파일 경로 제안 (app/[카테고리]/[페이지].html)
   ├── 사용할 API 엔드포인트
   └── 스타일 가이드 적용 방식

2️⃣  대표님 승인 후 구현
   ├── 전체 코드 파일 제공
   ├── 필수 CSS/JS 파일도 함께 제공
   └── 설명 함께 제공

3️⃣  스타일 검증
   ├── 사이드바/탑바와 일관성 확인
   ├── 버튼/카드 시스템 일치 확인
   └── 배지/배경색 시스템 일치 확인

4️⃣  CURRENT_STATUS.md 업데이트
   ├── 완료된 작업 기록
   ├── 변경사항 반영
   └── 다음 작업 갱신
```

### 13.2 코드 제공 방식

- **전체 파일 단위 제공**: 부분 수정이 아닌 전체 파일을 제공하여 복사/붙여넣기 시 오류 없음
- **경로 정확히 작성**: Vite 기준 절대/상대 경로 명시
- **주석 포함**: 보안(SQLi 방어 등)이나 레이아웃 변경 시 이유를 함께 설명

## 14. 보안 가이드

### 14.1 필수 보안 규칙

| 규칙 | 설명 |
|------|------|
| **SQL Injection 방지** | 무조건 Parameterized Queries (`db.prepare().bind()`) 사용 |
